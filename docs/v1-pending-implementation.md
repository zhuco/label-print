# 第一版发布验收与待办

状态：**代码功能已完成，等待生产环境与真机验收**  
最后更新：2026-08-07

目标版本：第一版正式发布

## 1. 第一版功能结论

以下用户可见功能已完成实现，并已有对应自动化测试覆盖：

- 注册、登录、退出、忘记密码与重置密码流程；
- 默认保持登录：凭据存放在 Windows 凭据管理器，启动时自动恢复会话，主动退出才清除；
- `.lpt` 本地保存、云端保存、离线队列、冲突处理和个人标签空间；
- 图片元素及云端图片资源上传、下载和缓存；
- 免费版 50 个、专业版 200 个标签的服务端硬性配额；创建、复制、官方模板创建、永久删除和同步成功后，桌面端会重新读取服务端配额；
- CSV/Excel 导入、字段绑定、多记录逐行渲染，并输出到 Windows 打印机或多页 PDF；总张数为 `数据行数 × 每行份数`；
- 应用更新：签名的版本化完整安装包、stable/beta 渠道、灰度比例、最低支持版本、强制更新策略和安装安全拦截。

第一版中的“增量更新”定义为持续发布新版本并由客户端安全升级到新版本。当前采用完整签名更新包，这是 Tauri updater 原生支持、可验证且可回退的发布路径；**二进制差分补丁不是第一版发布前置条件**，已转为 P1 优化。

## 2. 本次完成项与验收证据

### 2.1 配额实时刷新（已完成）

- 登录会话新增 `refreshProfile()`，从 `/me` 重新读取服务端权威的套餐和用量。
- 云标签创建、复制、官方模板创建、永久删除及成功同步后均触发刷新。
- 服务端继续作为最终裁决者：回收站中的标签仍占名额，永久删除才释放名额；并发创建超过上限时仅限额内请求成功。
- 自动化测试验证用量从 49 变为 50 后，创建资格立即变为不可用。

### 2.2 CSV/Excel 多记录逐行打印（已完成）

- 打印弹窗会逐条切换绑定记录并生成独立预览位图，不再将首条记录重复打印。
- Windows 打印和 PDF 导出均接收多张位图；PDF 为每条记录、每份副本建立一页。
- 例如 3 条数据、每条 2 份会得到 6 张/页，顺序为第 1 条两份、第 2 条两份、第 3 条两份。
- 自动化测试验证两条不同 SKU 会生成两个不同的打印位图；Rust 测试验证两条记录、两份副本生成至少四个 PDF 页面。

### 2.3 更新发布能力（第一版方案已完成）

- 桌面端仅安装经过 updater 签名验证的完整更新包。
- 服务端按渠道、平台、架构、灰度比例、最低支持版本和强制更新策略返回兼容的发布记录。
- 更新安装在打印、未同步修改、导入/导出或资源上传等不安全状态下会被拦截。
- 发布时必须提供安装包、`.sig`、SHA-256 和版本发布记录。

## 3. 发布前必须由部署环境完成的验收

下列项目依赖正式域名、私钥、第三方服务或真实硬件，无法在仓库内替代。完成后第一版即可发布：

1. 部署正式 HTTPS API、PostgreSQL、S3 兼容对象存储、受限 CORS 和 SMTP；完成备份、恢复与密钥轮换演练。
2. 生成并离线备份 Tauri updater 私钥，将公钥编译进正式安装包；使用受信任证书签名 Windows 安装包和更新产物。
3. 上传更新产物、`.sig` 和 SHA-256，创建正式 release；在干净 Windows 10/11 x64 机器上演练“旧版安装 → 保持登录 → 检查更新 → 安装新版 → 数据可用”。
4. 使用至少两类常见热敏打印机和一个 PDF 打印目标，验证 40×30 mm、70×40 mm 等常用尺寸的边距、中文、条码可扫描性、图片清晰度与多记录顺序。
5. 若第一版对外销售专业版：接入真实支付渠道、验签、退款/到期同步；未接入前不得在发布页承诺在线购买。
